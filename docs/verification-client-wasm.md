# Client WASM移行の検証

## 変更範囲

解析・ピーク計測・左右共通ノーマライズ・WAV書き出しをブラウザのWeb Workerへ移した。Cloudflareは静的配信のみ。音声API、R2、cron、Paid専用CPU設定を削除した。

可視化の強化とM5補正EQは [TODO.md](TODO.md) の別工程として残し、実装していない。

移行前のHEAD `616e7b2` にローカルタグ `worker-wasm-before-client` を作成。前回作業の未コミットのビルド・CI整備はタグに含まない。

## ローカルでの確認

環境: Windows、Node.js 24.22.1、Rust 1.98.1、wasm-bindgen 0.2.129。ブラウザテストにはインストール済みEdgeをヘッドレスで使用。

- ブラウザ用WASM生成に成功。
- TypeScriptの型チェックに成功。
- クライアントの5テストに成功。
  - 31秒ステレオの分割解析が連続解析と一致。
  - 30秒の処理境界をまたぐ切り出し、出力フレーム数、左右比、-1 dBFSピークを確認。
  - ノーマライズなしの再書き出しで、指定区間のPCMバイト列が原本と一致。
  - 無音monoのストリーム書き出し、破損WAV・非有限PCM・不正範囲の拒否を確認。
  - ローカル一時保存を使えない場合の256 MiB制限が、音声を読む前に適用されることを確認。
- 実ブラウザの2テストに成功。
  - Web WorkerとWASMで解析し、指定範囲をダウンロード。範囲を変えた再書き出しも成功。
  - ブラウザコンテキストの通信を記録し、音声の送信（POST/PUT）や `/api/` アクセスがないことを確認。
  - OPFSが利用できない環境を再現し、Blob経由でも無音WAVを書き出せることを確認。
- `wrangler deploy --dry-run` 成功。12個の静的アセットを認識し、`No bindings found` を確認。

Node上の参考ベンチマーク: 30秒ステレオの特徴抽出244 ms、120分相当の合成特徴データ集約60 ms、30秒ステレオのゲイン処理等57 ms。確保済みWASM線形メモリは最大45.44 MiB。端末によって変わる値であり、全プロセスのメモリ量や120分PCM全体の解析時間ではない。
