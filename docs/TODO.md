# 実装の順序

機能を一度に実装せず、各段階の動作を確認してから次へ進む。

## 1. Client WASMへ移行（完了）

- [x] 解析・切り出し・左右共通ノーマライズをブラウザのWeb Worker内で完結させる。
- [x] 音声のアップロード、R2、サーバー側の音声処理、Paid専用設定を取り除く。
- [x] ファイルを小分けに読み、長い録音を原本ごとメモリへ展開しない。
- [x] 既存の波形・境界入力・試聴を維持し、書き出しを検証する。
- [x] CloudflareはHTML/JS/WASMの静的配信に使う。Git連携向けのWASMビルド設定を用意する（実接続・デプロイは未実施）。

移行前のコミット: `worker-wasm-before-client` → `616e7b2`。タグ作成時点の未コミットのビルド・CI整備は含まない。

## 2. トリミング位置の可視化（完了）

- [x] 自動検出した開始・余韻の終わり・拍手の開始を波形上へ重ねる。
- [x] 残す区間と削る区間、検出候補と手動補正後の境界を判別できるようにする。
- [x] 境界付近の拡大表示と試聴で、どこで切れるか確認できるようにする。
- [x] 表示と出力のサンプルフレームを一致させる。楽章間は保持する。

点線の候補・元の自動境界、緑の保存境界、保持する楽章間候補を表示する。手動調整後も検出候補を残し、自動範囲へ復元できる。二つの楽章・楽章間の無音・拍手を含む合成音声で、サンプル単位の出力一致と楽章間の保持を検証済み。

## 3. RØDE M5の周波数特性を打ち消す自動EQ（完了）

- [x] メーカー公式の周波数特性グラフを取得し、出典・版・測定条件と数値化した曲線を保存する。
- [x] ユーザーの方針どおり、そのグラフを基準とした逆特性のEQを設計する。録音個別の自動音質推定とは分ける。
- [x] 適用対象がM5の録音であることを設定で明示し、他のマイクの録音に誤適用しない。
- [x] 高低域の極端な逆補正を避ける帯域・最大ブースト・平滑化を決め、補正曲線を確認できるようにする。
- [x] 同じフィルターを左右に適用し、チャンク間でもフィルター状態を保持する。
- [x] EQ適用後のピークを基準にノーマライズし、クリッピングを防ぐ。
- [x] EQあり／なしの試聴と書き出しの一致を確認する。

公式DS V02のベクトルグラフを数値化し、出典・PDFハッシュ・未記載の測定条件・補正設計を[m5-eq.md](m5-eq.md)に記録した。M5補正は明示的なオプトイン。EQ試聴は書き出しと同じ処理のWAVを再生する。指定の247秒の[実録音での検証](verification-real-recording.md)でも全バイト一致・−1 dBFSを確認済み。

## 実録音での追加検証（完了）

- [x] 指定WAVのBWFメタデータを含む形式を確認し、ブラウザで読み込む。
- [x] 拍手を未検出とする問題を再現し、音色の変化と複数アタックで候補を検出する。
- [x] 小さい最初の拍手までさかのぼり、50 ms手前を切り出し終端にする。
- [x] 単発の衝撃音を拍手と誤判定しない回帰テストを追加する。
- [x] 実録音のEQ試聴・保存・出力ピークを確認する。
