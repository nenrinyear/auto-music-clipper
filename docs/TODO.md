# 実装の順序

機能を一度に実装せず、各段階の動作を確認してから次へ進む。

## 1. Client WASMへ移行（今回）

- [x] 解析・切り出し・左右共通ノーマライズをブラウザのWeb Worker内で完結させる。
- [x] 音声のアップロード、R2、サーバー側の音声処理、Paid専用設定を取り除く。
- [x] ファイルを小分けに読み、長い録音を原本ごとメモリへ展開しない。
- [x] 既存の波形・境界入力・試聴を維持し、書き出しを検証する。
- [x] CloudflareはHTML/JS/WASMの静的配信に使う。Git連携向けのWASMビルド設定を用意する（実接続・デプロイは未実施）。

移行前のコミット: `worker-wasm-before-client` → `616e7b2`。タグ作成時点の未コミットのビルド・CI整備は含まない。

## 2. トリミング位置の可視化（次の独立した変更）

- [ ] 自動検出した開始・余韻の終わり・拍手の開始を波形上へ重ねる。
- [ ] 残す区間と削る区間、検出候補と手動補正後の境界を判別できるようにする。
- [ ] 境界付近の拡大表示と試聴で、どこで切れるか確認できるようにする。
- [ ] 表示と出力のサンプルフレームを一致させる。楽章間は保持する。

既存の全体波形・選択区間表示は第1段階で維持し、この強化は同時に実装しない。

## 3. RØDE M5の周波数特性を打ち消す自動EQ（さらに後の独立した変更）

- [ ] メーカー公式の周波数特性グラフを取得し、出典・版・測定条件と数値化した曲線を保存する。
- [ ] ユーザーの方針どおり、そのグラフを基準とした逆特性のEQを設計する。録音個別の自動音質推定とは分ける。
- [ ] 適用対象がM5の録音であることを設定で明示し、他のマイクの録音に誤適用しない。
- [ ] 高低域の極端な逆補正を避ける帯域・最大ブースト・平滑化を決め、補正曲線を確認できるようにする。
- [ ] 同じフィルターを左右に適用し、チャンク間でもフィルター状態を保持する。
- [ ] EQ適用後のピークを基準にノーマライズし、クリッピングを防ぐ。
- [ ] EQあり／なしの試聴と書き出しの一致を確認する。

第1段階ではEQや補正用の仮の数値を実装しない。
