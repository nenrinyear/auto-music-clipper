# RØDE M5公称特性の補正

## 出典と数値化

- 出典: [RØDE公式 M5 Matched Pair datasheet DS V02](https://edge.rode.com/pdf/products/48/M5_Matched_pair_DS_V02.pdf)、2ページの赤い周波数特性曲線。
- 取得日: 2026-10-31。
- PDF SHA-256: `794a22dafbe4da42a6464116d5900cc5303a18ab08efc6711d3df6f23726efc5`。
- 資料のグラフには測定距離・測定治具・個体別条件の記載がないため、これらを推定で補っていない。公称グラフの近似であり、個体や部屋を実測した校正ではない。
- 赤い線は塗りつぶされたベクトル輪郭である。PDFのBezier曲線を標本化し、各周波数で上下の輪郭の中心を採る。周波数軸は20 / 100 / 1,000 / 10,000 / 20,000 Hzの目盛で対数補間し、0 dBのY座標710.8407、1 dBあたり1.4202 PDFポイントで変換する。
- 20 Hzから20 kHzまで対数間隔121点を保存し、1 kHzを0 dB基準にする。元の数値・軸座標・出典・係数は [m5-profile.js](../web/src/m5-profile.js) に保存する。

再生成には開発用のPython、numpy、pdfplumberを使用する。アプリ実行時や通常のWASMビルドには不要。

```sh
python web/scripts/digitize-m5.py path/to/M5_Matched_pair_DS_V02.pdf
```

## 補正の設計

プロファイルIDは `rode-m5-ds-v02-v1`。数値化した公称特性を対数周波数上の5点、重み1:2:3:2:1で平滑化し、符号を反転する。公称特性の落ち込みを逆補正すると、録音に含まれる低域の振動や高域のノイズも増幅する可能性がある。20–80 Hzと16–20 kHzでは帯域の端に向けて目標補正を0 dBに近づける。目標補正は±3 dB以内に制限し、固定Qの9段のpeaking biquadへ最小二乗で近似する。

121点の検証グリッド上の実際の合成補正は約−2.620～+0.433 dB、目標に対するRMS近似誤差は約0.165 dB。これは数値近似の誤差であり、マイクの実測精度を示す値ではない。48 kHzでは保存済みの係数を使い、それ以外は元のサンプリングレートで係数を計算する。画面には公称特性と、そのレートで適用する補正EQを表示する。左右で同じ係数を使い、遅延状態だけをチャンネルごとに分離する。

## 適用順序と試聴

「RØDE M5で録音した音声を補正する」をユーザーが有効にした場合だけ適用する。初期状態はオフ。録音内容からマイクを自動判定しない。

1. 元音声の選択区間を読む。直前の最大0.5秒をフィルターの初期化に使い、出力・ピーク測定には含めない。
2. 30秒単位でEQ処理し、フィルターの状態を次のチャンクへ引き継ぐ。
3. ノーマライズ有効時は、EQ後の選択範囲全体の左右最大ピークから共通ゲインを求める。左右のうち大きいピークが目標値に達するように調整する。
4. 同じ初期化・EQ処理を再実行し、左右共通ゲインを一度適用してfloat32 WAVへ保存する。

EQ有効時の試聴は、この書き出し処理で作成した同じWAVを再生する。OPFS対応環境では一時ファイルへ小分けに保存し、非対応環境では既存の256 MiB上限のBlobを使う。録音全体をPCM配列へ展開しない。範囲・ピーク上限・ノーマライズ設定が同じなら試聴データを再利用する。シーク表示は元録音の時刻へ換算し、EQ試聴は選択範囲の最後で終了する。保存ファイル名は `_clip_m5.wav` になる。

EQ無効時は従来どおり、元WAVを再生して共通GainNodeでノーマライズする。ノーマライズをオフにした場合は、EQ有効でもピーク調整を行わない。float WAV自体は1を超えるサンプルを保持できるため、再生時のクリッピングを避ける通常の使い方ではノーマライズを有効にする。

## 検証

- 連続処理と任意のチャンク分割の結果が一致すること、左右の比率を保持すること、無音側へ混合しないことをテストする。
- フィルターの安定性、8 kHzで約2～3 dBを抑制する応答、30秒境界の前後のサンプル連続性を確認する。
- EQ後のピークでノーマライズし、指定ピーク上限に達することを確認する。
- ブラウザでEQ試聴と書き出しの全バイト一致、オン／オフ、区間変更後の再生成、準備中の停止、元録音の時刻によるシークを検証する。
- 指定された247秒の実録音でも、試聴と保存のSHA-256一致・−1 dBFSの出力ピークを確認した。[実録音の検証記録](verification-real-recording.md)を参照。
